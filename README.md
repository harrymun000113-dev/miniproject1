# Blue Ocean Finder
### 무역 기회 발굴 대시보드 — KITA AX 무역마스터 1차 프로젝트

---

## 프로젝트 개요

특정 HS CODE를 기준으로 전 세계 국가를 자동 분석하여, **"시장 수요와 성장성은 높지만 한국산 제품의 시장 침투율은 상대적으로 낮은 국가"** 를 찾아주는 서비스입니다.

기존의 단순한 "수출 유망국가 추천" 서비스와 달리, 한국이 아직 충분히 진출하지 못한 미개척 시장(Blue Ocean Market)을 찾는 것이 핵심입니다.

> "한국이 아직 놓치고 있는 시장을 찾습니다."

HS CODE 하나를 입력하면 아래 결과를 한 화면에서 볼 수 있습니다.

| 결과 | 내용 |
|---|---|
| 전체 마켓 사이즈 | 입력한 HS CODE 품목의 전 세계 총 수입 규모 (USD) |
| 1위 추천 타깃 | Blue Ocean Score 1위 국가와 추천 이유 |
| 랭킹 대시보드 | 상위 20개 타깃국의 점수, 포텐셜, 한국기업 침투도(%), 경쟁국, 해당 HS CODE 수입 규모 |
| 국가 상세 분석 | 왜 블루오션인가 (Export Gap, 경쟁국, 계절성·진출 타이밍) |
| 관련 박람회 | HS CODE와 연관된 박람회 일정 |

---

## 문서 구성 (읽는 순서)

이 프로젝트는 문서를 역할별로 분리해서 관리합니다. **코드를 짜기 전에 아래 순서로 먼저 읽으세요.**

1. **`README.md`** (이 문서) — 프로젝트 전체 개요
2. **`BLUE_OCEAN_SCORE.md`** — 알고리즘 명세서 (깔때기 규칙, 100점 스코어링 공식, 절대 임의 변경 금지)
3. **`DATA_SCHEMA.md`** — 데이터 컬럼 정의, API 소스 확정 정보
4. **`TEAM_RULES.md`** — 협업 규칙, Git 규칙, AI에게 작업 요청 시 프롬프트 템플릿

어떤 AI(GPT, Gemini, Claude, Cursor 등)로 코드를 짜든, 이 3개 문서(`BLUE_OCEAN_SCORE.md`, `DATA_SCHEMA.md`, `TEAM_RULES.md`)를 먼저 주고 작업을 시작해야 합니다.

### 왜 이렇게 하나요?

팀원마다 다른 AI로 바이브코딩을 하기 때문에, 문서 없이 각자 코드를 요청하면 변수명·공식·데이터 흐름이 서로 어긋납니다. 이 문서들은 **어떤 AI든 프로젝트의 맥락(무엇을 만드는지), 구조(데이터가 어떤 순서로 흐르는지), 규칙(바꾸면 안 되는 것)을 먼저 파악한 뒤 거기에 맞춰 코딩하게 하기 위한 공통 컨텍스트**입니다.

## 핵심 서비스 흐름 (깔때기 Funnel 방식)

전 세계 모든 국가에 비싼 API 호출을 하면 호출 한도와 시간이 부족하고, 랜덤 샘플링은 결과가 부정확하고 매번 달라집니다. 그래서 **비용이 들지 않는 간이 점수로 전 국가를 먼저 걸러내고, 정밀 수집과 최종 점수는 상위 50개국에만 적용**합니다.

```
[STEP 1] HS코드 입력 → UN Comtrade(또는 K-Stat)로 국가별 수입 데이터 수집 (다년도)
      ↓
[STEP 2] 하드 컷: 해당 품목 수입금액 500만 달러 이하 국가 제외
      ↓
[STEP 3] 간이 점수(proxy_score)로 남은 전체 국가 순위화 (추가 API 호출 없음)
      ↓
[STEP 4] 간이 점수 상위 50개국 선별 (이 규칙 하나만 사용, 랜덤/층화추출 없음)
      ↓
[STEP 5] 50개국에만 추가 데이터 수집 → 100점 만점 최종 점수 산출
      ↓
[STEP 6] 결과 출력
         ├─ 전체 마켓 사이즈
         ├─ 1위 추천 타깃
         ├─ 랭킹 대시보드 TOP 20
         ├─ 선택 국가 상세 분석 (Export Gap, 경쟁국, 진출 타이밍)
         └─ 관련 박람회 일정
```

- 같은 HS CODE를 넣으면 항상 같은 결과가 나와야 합니다 (재현성).
- 세부 공식과 배점은 `BLUE_OCEAN_SCORE.md`, 컬럼과 API 정의는 `DATA_SCHEMA.md`를 따릅니다.

## 스코어링 요약 (100점 만점)

| 구분 | 지표 | 배점 |
|---|---|---|
| 시장 매력 (50) | 전체 시장 규모 | 15 |
| | 3년 CAGR | 15 |
| | 전년 대비 성장률 | 10 |
| | Google 트렌드 | 5 |
| | 최근 3년 환율 추이 | 5 |
| 한국 침투 여지 (50) | 시장규모 대비 한국 수출 비중 (낮을수록 高) | 25 |
| | 경쟁 개방성 (상위 3개 수출국 점유율, 낮을수록 高) | 15 |
| | 관세 (낮을수록 高) | 10 |

정확한 공식과 결측 처리 규칙은 `BLUE_OCEAN_SCORE.md`를 참고하세요.

## 랭킹 대시보드 구성

| 순위 | 국가 | Blue Ocean Score | Potential | 한국기업 침투도(%) | 경쟁국(상위 3) | 수입 규모(해당 HS CODE, USD) |
|---|---|---|---|---|---|---|

- 마지막 열은 기존 KOTRA 열을 대체해 **해당 국가의 HS CODE 품목 수입 규모**를 보여줍니다.
- 박람회 일정은 랭킹 표가 아니라 별도 "관련 박람회" 영역에서 보여줍니다.

## 팀 역할 분담

| 담당 | 모듈 | 파일 |
|---|---|---|
| A | 데이터 수집 (Comtrade/K-Stat, 환율, 트렌드, 박람회) | `src/collect_data_A.py` |
| B | 전처리·KPI·Export Gap 계산, 간이 점수·상위 50 후보 선별 | `src/preprocess_kpi_B.py` |
| C | 100점 스코어 산출 (Potential, Blue Ocean Score, 순위) | `src/score_engine_C.py` |
| D | 경쟁국 분석·인사이트·계절성(진출 타이밍) | `src/insight_D.py` |
| E | 대시보드·배포 | `src/dashboard_E.py` |

## 데이터 출처

데이터는 **API와 크롤링**으로 수집합니다.

- UN Comtrade API 또는 K-Stat API (국가×품목별 수입·한국발 수입·공급국 구성)
- 환율 API (환율 추이)
- Google Trends (검색 관심도)
- 관세 데이터 (소스 확정 필요)
- 박람회 일정 (KOTRA 해외전시회 정보 및 크롤링)

상세 확보 방법과 확정 여부는 `DATA_SCHEMA.md` 6번 섹션 참고.
